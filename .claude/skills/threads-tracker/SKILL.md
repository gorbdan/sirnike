# Threads Tracker v2 — разведка, замеры, анализ

Ведёт «Трекер конкурентов» — таблицу аккаунтов ниши с еженедельными замерами
подписчиков. Умеет сам находить новые аккаунты, сам снимать цифры (метод
проверен в бою 17.07.2026), считать прирост и разбирать механику лидеров.

## Данные

- Таблица: страница **«15. Threads — анализ быстрорастущих аккаунтов»**,
  page_id `39e0370b-60f7-81b1-a325-f6caf49d9d93`, секция «Трекер конкурентов».
- Хаб: «Сырник — Маркетинг», page_id `38a0370b-60f7-813a-bb1a-e8bd16de6edd`.
- Колонки: Аккаунт · Тип · Замер 1..N (дата) · Заметки.
- Notion MCP: `notion-fetch` перед записью (в хранимом формате ячейки `<td>`
  разделены переводами строк — `old_str` для `update_content` должен
  совпадать байт в байт). Новые строки добавлять заменой
  «последняя строка + `</table>`» → «последняя строка + новые строки + `</table>`».

## Ключевой механизм: og-замер (работает без браузера)

Meta отдаёт краулерам SSR-метаданные профиля. Требование: в network policy
окружения разрешены `threads.com` / `www.threads.com` (если нет — сначала
проверить `curl -s -o /dev/null -w "%{http_code}" https://www.threads.com/@zuck`;
при 000/403 попросить пользователя открыть сеть или прислать скриншоты).

```bash
curl -s --max-time 20 -A "facebookexternalhit/1.1" \
  "https://www.threads.com/@HANDLE" | \
  grep -o -E '<meta (property="og:description"|name="description") content="[^"]*"' | head -1
# → content="11.3K Followers • 25 Threads • <bio>. See the latest..."
```

- Парсить: подписчики (`11.3K`→11 300, `1.6K`→1 600, `585`→585), число
  постов («N Threads»), био (HTML-entities декодировать).
- Часть профилей отдаёт только `name="description"` без og — проверять оба.
- Если пусто — повторить с UA `Googlebot/2.1 (+http://www.google.com/bot.html)`.
- Пауза 1–2 сек между запросами. Точность K-формата ~сотни — фиксировать
  в заголовке колонки замера.

## Режим 0 — Разведка ниши (поиск новых аккаунтов)

Триггер: «найди аккаунты/конкурентов», список меньше цели (30–50), или
еженедельно вместе с замером.

1. WebSearch по связкам: `site:threads.com` + ключи ниши — «нейрофотосессия»,
   «нейрофото», «AI фото аватар», «фото бот нейросеть», «AI creator фото»;
   плюс без site: «threads.com нейрофотосессия блог». 3–5 запросов.
2. Из выдачи собрать все URL вида `threads.com/@handle` (и `/@handle/post/…` —
   из них тоже извлекается handle). Дедуп против таблицы.
3. Каждого кандидата прогнать через og-замер → подписчики, посты, био.
4. Фильтр: русскоязычное био ИЛИ явная ниша (нейрофото/AI/фотосессии);
   подписчики 300–100 000 (меньше — шум, больше — не наша лига);
   живой аккаунт (посты есть). Прямые конкуренты (свой бот/продажа
   нейрофотосессий) проходят фильтр всегда и помечаются ⚠️.
5. Показать пользователю найденных с цифрами, добавить в таблицу
   (по умолчанию — всех прошедших фильтр, если пользователь не просил отбор).

## Режим 1 — Ручной ввод (скриншоты/текст)

Пользователь присылает скриншоты профилей или «марианна 12к, тая 3400».
Извлечь handle→число («12,5 тыс.»=12 500, «1,2 млн»=1 200 000), найти
первую пустую колонку «Замер N», записать. Не видно ника/числа — спросить,
не угадывать.

## Режим 2 — Замер

Триггер: «сними замер», прошло ≥7 дней с последнего, или после разведки.

1. `notion-fetch` таблицы → список handle.
2. og-замер по каждому (bash-цикл, sleep 1–2).
3. Записать в первую пустую колонку «Замер N (дата)». Если колонки
   кончились — добавить новую в заголовок и все строки.
4. Аккаунты, у которых og пустой дважды, пометить в Заметках
   «проверить вручную» — не выдумывать.

## Режим 3 — Анализ

Триггер: «кто растёт», «проанализируй», автоматически при ≥2 замерах.

1. Прирост абсолютный и % (нормировать на неделю). Отсортировать.
2. Эффективность: подписчики / число постов — отдельный рейтинг
   (пример из Замера 1: 138 постов → 14,2K лучше, чем 946 → 1,6K).
3. Топ-3 быстрорастущих — разбор механики: WebSearch
   `site:threads.com/@handle` даёт тексты залетевших постов из выдачи;
   разбирать хуки/структуру по критериям стр. 15 (94% хук, 40–120 слов,
   вопрос, одна мысль). Механику — брать, тексты — никогда (safe remix).
4. Вывод: 2–3 «что взять» для календаря стр. 17 + «что у них не работает».
5. Прямых конкурентов (⚠️) разбирать каждый замер, даже вне топа.

## Жёсткие правила

1. Не выдумывать и не «оценивать примерно» цифры. Нет данных — пусто + честное сообщение.
2. Каждый замер с датой; все аккаунты в один день.
3. Строки не удалять (история дороже); мёртвые аккаунты помечать в Заметках.
4. Данные — только в Notion, не в git (правило Ани про маркетинговые материалы).
5. Ничего не публиковать в Threads; контент-страницы (16, 17, 19) не трогать.
6. Если прошло >8 дней с последнего замера — напомнить при любом запуске.
