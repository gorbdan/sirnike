# Threads Tracker — трекер конкурентов Сырника

Скилл ведёт «Трекер конкурентов» — таблицу еженедельных замеров подписчиков
Threads-аккаунтов ниши (AI-фото, нейрофотосессии, лайфстайл). Цель: через 3–4
замера получить собственный рейтинг быстрорастущих аккаунтов ниши и разбирать
их механику для стратегии обгона.

## Где лежат данные

- Таблица: Notion-страница **«15. Threads — анализ быстрорастущих аккаунтов»**,
  page_id `39e0370b-60f7-81b1-a325-f6caf49d9d93`, секция
  «Трекер конкурентов (рабочая таблица — заполнять сюда)».
- Хаб: «Сырник — Маркетинг», page_id `38a0370b-60f7-813a-bb1a-e8bd16de6edd`.
- Колонки: Аккаунт · Тип · Замер 1 (дата) · Замер 2 · Замер 3 · Замер 4 ·
  Заметки. Работать через Notion MCP (`notion-fetch`, `notion-update-page`).
- Связанные документы хаба: стр. 14 (стратегия 30 дней), стр. 16 (30 веток),
  стр. 17 (календарь В/Э/Л/П), стр. 19 (переписанные посты).

## Жёсткие правила

1. **Никогда не выдумывать цифры.** Нет данных — клетка остаётся пустой,
   пользователю честно сообщается, каких аккаунтов не хватает.
2. **Каждый замер — с датой.** Дата пишется в заголовок колонки «Замер N
   (дата: DD.MM)». Все аккаунты по возможности замеряются в один день.
3. **Перед любым обновлением таблицы — `notion-fetch` страницы**, чтобы взять
   точное текущее представление строк. В хранимом формате Notion ячейки `<td>`
   разделены переводами строк — `old_str` в `update_content` должен совпадать
   с этим форматом байт в байт, иначе будет «No matches found».
4. Один аккаунт = одна строка навсегда. Новые аккаунты добавляются новыми
   строками (цель — 30–50), удалять строки нельзя: история дороже чистоты.
5. Ссылка на аккаунт в формате `[@handle](https://www.threads.com/@handle)`.

## Режим 1 — Ввод данных (скриншоты или текст)

Триггер: пользователь присылает скриншоты профилей или пишет цифры текстом
(«марианна 12к, тая 3400…»).

1. Извлечь пары handle → число подписчиков. Из скриншота брать число под
   именем профиля; «12,5 тыс.» = 12 500; «1,2 млн» = 1 200 000. Если на
   скриншоте не видно ника или числа — спросить, а не угадывать.
2. Определить номер замера: первая пустая колонка «Замер N» слева направо
   для этой строки. Если все четыре заполнены — добавить колонку «Замер 5»
   и далее (таблицу расширять, историю не затирать).
3. Если аккаунта нет в таблице — добавить строку и спросить/определить «Тип»:
   **личный блог** (лицо, истории, свои «до») / **агрегатор** (подборки
   промтов и ботов без лица) / **эксперт** (обучение, разборы). Конкуренты
   с собственным фото-ботом помечаются в Заметках «⚠️ ПРЯМОЙ КОНКУРЕНТ».
4. Обновить строки через `notion-update-page` → `update_content`.
5. Отчитаться: сколько строк обновлено, какие аккаунты остались без цифр.

## Режим 2 — Анализ прироста

Триггер: «кто растёт», «проанализируй трекер», либо автоматически после
ввода данных, когда у ≥5 аккаунтов есть ≥2 замера.

1. Для каждого аккаунта с ≥2 замерами посчитать прирост: абсолютный и в %
   за период между замерами (нормировать на неделю, если интервал другой).
2. Отсортировать по темпу прироста, выделить топ-3 быстрорастущих.
3. Для топ-3 — мини-разбор механики по критериям стр. 15: какие хуки
   в первой строке, частота постинга, форматы (текст/визуал/интерактив),
   как встроен оффер. Данные для разбора запрашивать у пользователя
   (скриншоты 2–3 топовых постов аккаунта), если сеть закрыта.
4. Вывод: 2–3 конкретных «что взять» (механику, не тексты — правило
   safe remix) и «что у них не работает» — для календаря стр. 17.
5. Итог замера записать одной строкой в Заметки страницы или сообщить в чат.

## Режим 3 — Автозамер (если доступна сеть)

Перед ручным запросом всегда проверять, не открылся ли прямой путь:

```bash
curl -s -o /dev/null -w "%{http_code}" --max-time 10 https://www.threads.com/@zuck
```

- **200** → сеть открыта: для каждого аккаунта из таблицы забрать страницу
  профиля и извлечь число подписчиков из meta-описания
  (`og:description` содержит «N Followers»). Заполнить замер полностью
  автоматически, отчитаться.
- Есть `SCRAPECREATORS_API_KEY` в окружении → проверить
  `https://api.scrapecreators.com/v1/threads/profile?handle=<handle>`
  (заголовок `x-api-key`). Работает → использовать его. Лимит бюджета:
  не более 12 запросов на один замер.
- **000/403** (заблокировано сетевой политикой) → не мучить сеть повторами;
  перейти в Режим 1: попросить у пользователя скриншоты, объяснив одной
  строкой, почему автоматически нельзя.

## Каденция

Замер — раз в неделю, в один и тот же день недели. Если с последнего замера
прошло больше 8 дней, при любом запуске скилла напомнить пользователю, что
пора переснять цифры. После 4-го замера предложить свернуть выводы в отчёт
(«7. Шаблон отчёта» в хабе) и почистить список от мёртвых аккаунтов
(прирост ~0 три недели подряд) — не удаляя строки, а помечая в Заметках.

## Чего скилл не делает

- Не публикует ничего в Threads и не трогает контент-страницы (16, 17, 19).
- Не выдумывает и не «оценивает примерно» цифры подписчиков.
- Не хранит данные в git — только в Notion (правило Ани: маркетинговые
  материалы живут в Notion-хабе).
