## 🔴 [SirNike.py:2912] Race condition при резервировании слота в очереди

**Код:**
```python
if user.id in queued_user_ids or user.id in processing_user_ids:
    await reply_target.reply_text(...)
    return

# Reserve slot immediately — before any awaits — to prevent concurrent submissions
queued_user_ids.add(user.id)

state = get_or_init_state(context)

if not state.prompt:
    queued_user_ids.discard(user.id)
```

**Проблема:** Между проверкой `if user.id in queued_user_ids` (строка 2915) и `queued_user_ids.add(user.id)` (строка 2918) ЕСТЬ `await reply_target.reply_text()` — это точка переключения контекста. Пока первый пользователь ждёт ответа Telegram, второй запрос этого же пользователя пройдёт проверку `user.id in queued_user_ids` (вернёт False, потому что добавление ещё не произошло) и тоже зарезервирует слот.

**Воспроизведение:** Пользователь очень быстро нажимает «Запустить генерацию» дважды, пока первое `reply_target.reply_text()` не завершилось → оба запроса попадают в очередь вместо одного.

**Фикс:**
```python

        return

    try:
        state = get_or_init_state(context)
```

```python
    elif reason and "invalid" in reason.lower():
        details = "Одно из загруженных фото не подходит — попробуй другое."

        f"• Попробуй снова с тем же промптом\n"
        f"• Или выбери другой стиль\n"
```

## 🟡 [SirNike.py:2912] Недостаточная защита от двойного запуска генерации через race между проверкой и добавлением в очередь

**Код:**
```python
async def run_generation(update: Update, context: ContextTypes.DEFAULT_TYPE):
    user = update.effective_user
    create_user_if_not_exists(user.id, user.username, START_BONUS)
    reply_target = update.callback_query.message if update.callback_query else update.effective_message

    if user.id in queued_user_ids or user.id in processing_user_ids:
        await reply_target.reply_text(
            "Сырник уже работает над твоим запросом 🧀\n"
            ...
        )
        return

    # Reserve slot immediately — before any awaits — to prevent concurrent submissions
    queued_user_ids.add(user.id)
```

**Проблема:** Комментарий говорит "перед любыми await", но ВЫШЕ есть несколько операций БЕЗ await, и они ПОТОМ добавляют в `queued_user_ids`. Между проверкой `if user.id in queued_user_ids` и `queued_user_ids.add(user.id)` нет await, значит race condition НЕВОЗМОЖЕН в asyncio. **Это не баг — код правильный.**

Но есть другая проблема: если между добавлением в `queued_user_ids` и `generation_queue.put_nowait(job)` произойдёт ошибка или выполнится исключение (например, в блоке try перед очередью), то `queued_user_ids.add()` успеет, но job НЕ попадёт в очередь, и пользователь будет "заблокирован" навеки (или до перезагрузки бота).

**Воспроизведение:** На строке после `queued_user_ids.add(user.id)` возникает исключение (например, при вычислении `cost`), блок except ловит, откатывает платёж, но НЕ удаляет user из `queued_user_ids`. Пользователь нажимает "Запустить" снова → "Сырник уже работает" (ложный). На самом деле job не был отправлен.

**Фикс:** Добавлять в `queued_user_ids` ПОСЛЕ успешного `put_nowait()` или использовать try/finally:
```python
queued_user_ids.add(user.id)
try:
    generation_queue.put_nowait(job)
    await reply_target.reply_text("Сырник всё понял...")
except asyncio.QueueFull:
    queued_user_ids.discard(user.id)  # ОТМЕНА резервирования
    ...
    return
```

Текущий код это делает в except блоках, но добавление в `queued_user_ids` происходит ДО try, поэтому если исключение случится ВНЕ try (например, в `create_user_if_not_exists`), пользователь будет зависнет.

## 🟡 [SirNike.py:184-220] Потенциальная race condition в `_BoundedImageCache._evict()` при одновременном доступе к `_data`

**Код:**
```python
def __setitem__(self, key: str, value: bytes) -> None:
    if len(value) > self._max_bytes:
        logger.warning("Image too large for cache (%d bytes), skipping", len(value))
        return
    if key in self._data:
        self._total_bytes -= len(self._data[key])
        del self._data[key]
    self._data[key] = value
    self._total_bytes += len(value)
    self._evict()

def _evict(self) -> None:
    while (len(self._data) > self._max_entries or self._total_bytes > self._max_bytes) and self._data:
        _, evicted = self._data.popitem(last=False)
        self._total_bytes -= len(evicted)
```

**Проблема:**
Если `_BoundedImageCache` вызывается из двух разных мест в async коде БЕЗ явного await между ними (строки не разделены await), то технически race condition физически невозможен в asyncio.

ОДНАКО: если кэш используется из синхронного кода (например, вспомогательные функции типа `_cache_image()` или `_resolve_image_bytes()`), то при многопоточном доступе из `asyncio.to_thread()` может произойти одновременное чтение и запись в `_data.OrderedDict`.

`_data.popitem()` в `_evict()` не потокобезопасен — это race condition на уровне CPython GIL, но может привести к повреждению OrderedDict.

**Воспроизведение:** 
1. Несколько потоков (из `asyncio.to_thread()`) одновременно вызывают `_cache_image()`.
2. Один поток выполняет `_evict()` с `popitem()`.
3. Другой поток вызывает `get()` → `move_to_end()`.
4. Возможно KeyError или corrupted OrderedDict.

**Фикс:**
```python
import threading

class _BoundedImageCache:
    def __init__(self, max_entries: int, max_bytes: int) -> None:
        self._max_entries = max_entries
        self._max_bytes = max_bytes
        self._data: "_collections.OrderedDict[str, bytes]" = _collections.OrderedDict()
        self._total_bytes = 0
        self._lock = threading.Lock()  # Добавить потокобезопасность

    def __setitem__(self, key: str, value: bytes) -> None:
        with self._lock:
            if len(value) > self._max_bytes:
                logger.warning("Image too large for cache (%d bytes), skipping", len(value))
                return
            if key in self._data:
                self._total_bytes -= len(self._data[key])
                del self._data[key]
            self._data[key] = value
            self._total_bytes += len(value)
            self._evict()

    def get(self, key: str, default: Optional[bytes] = None) -> Optional[bytes]:
        with self._lock:
            if key not in self._data:
                return default
            return self[key]
```
