## 🔴 [SirNike.py:3081] Потеря изюминок при краше между spend и put_nowait

**Код:**
```python
if not spend_izyminki(user.id, cost):
    # ...
    return
paid = True

try:
    # ... 20 строк кода ...
    generation_queue.put_nowait(job)
except asyncio.QueueFull:
    queued_user_ids.discard(user.id)
    if paid:
        add_izyminki(user.id, cost)
```

**Проблема:**  
Между `spend_izyminki()` (строка ~3081) и `generation_queue.put_nowait(job)` (строка ~3100) находится ~20 строк кода с логированием, кешированием, проверками. Если произойдёт необработанное исключение (например, в `_bounded_set()`, в логировании или в самой очереди), изюминки будут потеряны — возмещение происходит только в блоке `except asyncio.QueueFull`, который не ловит прочие исключения.

**Воспроизведение:**  
1. Пользователь запускает генерацию, изюминки списываются
2. В цикле `for` валидации refs происходит исключение (например, сетевая ошибка в `asyncio.gather`)
3. Исключение падает сквозь try-except (он ловит только `QueueFull`)
4. Job не попадает в очередь, но изюминки уже списаны → потеря средств

**Фикс:**  
```python
if not spend_izyminki(user.id, cost):
    # ... return
paid = True

try:
    # ... весь код ...
    generation_queue.put_nowait(job)
except Exception as e:  # Catch ALL, не только QueueFull
    queued_user_ids.discard(user.id)
    if paid:
        add_izyminki(user.id, cost)
    elif use_free:
        restore_free_generation(user.id)
    if not isinstance(e, asyncio.QueueFull):
        logger.exception("Unexpected error during job enqueue")
    raise
```

```python
            return_exceptions=True,
        )
    for (i, ref_url), result in zip(to_validate, results):
        if isinstance(result, Exception):
            ok_ref, reason_ref = False, str(result)
        else:
```

## 🟡 [SirNike.py:3095-3110] Неполная обработка исключений в блоке enqueue

**Код:**
```python
except asyncio.QueueFull:
    queued_user_ids.discard(user.id)
    if paid:
        add_izyminki(user.id, cost)
    elif use_free:
        restore_free_generation(user.id)
    logger.critical("Queue full: %d/%d", generation_queue.qsize(), generation_queue.maxsize)
    await reply_target.reply_text(...)
    return

except BaseException as _enqueue_exc:
    queued_user_ids.discard(user.id)
    if paid:
        add_izyminki(user.id, cost)
    elif use_free:
        restore_free_generation(user.id)
```

**Проблема:**  
Блок `except BaseException` ловит исключения, но находится **после** первого try-except на `asyncio.QueueFull`. Если `add_izyminki()` или `restore_free_generation()` внутри первого except-блока упадут, они не будут ловиться, и деньги не возместятся второй раз. Кроме того, `BaseException` ловит и `KeyboardInterrupt`, `SystemExit` — это может скрыть проблемы при shutdown.

**Воспроизведение:**  
1. `generation_queue.put_nowait(job)` падает с `QueueFull`
2. `add_izyminki()` в except-блоке падает (например, БД заблокирована)
3. Исключение выходит, изюминки не возместились
4. Второй except не поймает это, так как it's already handled

**Фикс:**  
```python
except asyncio.QueueFull:
    queued_user_ids.discard(user.id)
    try:
        if paid:
            add_izyminki(user.id, cost)
        elif use_free:
            restore_free_generation(user.id)
    except Exception as refund_err:
        logger.critical("Failed to refund after QueueFull: %s", refund_err)
        # Notify admin, но не молчи
    logger.critical("Queue full: %d/%d", generation_queue.qsize(), generation_queue.maxsize)
    await reply_target.reply_text(...)
    return

except Exception as _enqueue_exc:  # Not BaseException!
    queued_user_ids.discard(user.id)
    try:
        if paid:
            add_izyminki(user.id, cost)
        elif use_free:
            restore_free_generation(user.id)
    except Exception as refund_err:
        logger.critical("Failed to refund after exception: %s", refund_err)
    if not isinstance(_enqueue_exc, asyncio.CancelledError):
        logger.exception("Failed to enqueue generation job")
    raise
```

## 🟡 [SirNike.py:1726-1796] `_broadcast_running` флаг не защищен от race condition между проверкой и установкой

**Код:**
```python
global _broadcast_running
# ... code ...
if _broadcast_running:
    await update.message.reply_text("⚠️ Рассылка уже запущена...")
    return
_broadcast_running = True
try:
    # ... broadcast logic
finally:
    _broadcast_running = False
```

**Проблема:**  
Между проверкой `if _broadcast_running` (строка ~1748) и установкой `_broadcast_running = True` (строка ~1751) нет await, поэтому в asyncio это атомарно **в рамках одного handler'а**. **НО**: если два разных handler'а (например, `/broadcast_promo` и `/broadcast_text`) вызываются почти одновременно из разных корутин, они оба могут пройти проверку и оба установить флаг в True. Глобальный флаг в asyncio не атомарен против параллельных корутин без await между ними.

**Воспроизведение:**  
1. Админ вызывает `/broadcast_promo` в чате А
2. Одновременно админ вызывает `/broadcast_text` в чате Б
3. Обе корутины проверяют `if _broadcast_running:` одновременно, оба видят False
4. Обе начинают рассылать параллельно

**Фикс:**  
```python
_broadcast_lock = asyncio.Lock()

async def broadcast_promo(update, context):
    async with _broadcast_lock:
        if _broadcast_running:
            await update.message.reply_text("⚠️ Рассылка уже запущена...")
            return
        global _broadcast_running
        _broadcast_running = True
    try:
        # ... broadcast logic
    finally:
        async with _broadcast_lock:
            _broadcast_running = False
```

## 🟢 [SirNike.py:474] Потенциальная ошибка при использовании `_prompt_library_lock` до инициализации

**Код:**
```python
def _get_prompt_library_lock() -> asyncio.Lock:
    if _prompt_library_lock is None:
        raise RuntimeError("_prompt_library_lock used before post_init — call post_init first")
    return _prompt_library_lock
```

**Проблема:**  
Функция корректно проверяет инициализацию, но если `post_init()` не вызвана (что может случиться при неправильном старте бота), то любой вызов `_locked_save_and_refresh()` упадёт с RuntimeError, который может повалить handler без graceful fallback.

**Воспроизведение:**  
1. Бот стартует, но `post_init()` не вызывается (баг в main)
2. Админ пытается отредактировать библиотеку промптов
3. `_locked_save_and_refresh()` вызывает `_get_prompt_library_lock()`
4. Получает RuntimeError, handler падает

**Фикс:**  
```python
async def _locked_save_and_refresh(data: list) -> None:
    """Thread-safe save + reload of the prompt library. Use in async admin handlers."""
    try:
        lock = _get_prompt_library_lock()
    except RuntimeError as init_err:
        logger.critical("Prompt library lock not initialized: %s", init_err)
        raise ValueError("Библиотека промптов не инициализирована. Перезагрузи бота.") from init_err
    
    async with lock:
        await asyncio.to_thread(save_prompt_library, data)
        refresh_prompt_library()
```

## 🔴 [SirNike.py:1623] Недостаточная валидация payload при предоплатной проверке

**Код:**
```python
async def precheckout_callback(update: Update, context: ContextTypes.DEFAULT_TYPE):
    query = update.pre_checkout_query
    payload = query.invoice_payload
    try:
        parts = payload.split("_")
        if len(parts) < 3:
            raise ValueError("too few parts")
        count = int(parts[1])
        price = int(parts[2])
        if count <= 0:
            raise ValueError("non-positive count")
        valid_pack = next((p for p in BUY_PACKS if p["count"] == count and p["price"] == price), None)
        if valid_pack is None:
            raise ValueError(f"unknown pack count={count} price={price}")
    except Exception as e:
        logger.warning("Invalid precheckout payload %r from user %s: %s", payload, query.from_user.id, e)
        await query.answer(ok=False, error_message="Ошибка: неверный платёжный пакет.")
        return
    await query.answer(ok=True)
```

**Проблема:** Валидация не проверяет соответствие между `count` и `price` из payload с фактическими ценами в `BUY_PACKS`. Хотя проверка `valid_pack is None` отловит несуществующий пакет, код НЕ валидирует, что `count` и `price` соответствуют ЭТОМУ конкретному пакету (например, не проверяется, что они в правильном порядке). Также `parts[0]` (содержит "buy") не используется.

**Воспроизведение:** Злоумышленник может перехватить и модифицировать payload перед платежом (если somehow получит доступ), например поменять местами `count` и `price`: `buy_100_60` вместо `buy_60_100`. Строка `if valid_pack is None` отловит это, НО логика полагается на то, что пакет существует в правильном порядке.

**Фикс:** Явно проверить, что `parts[0] == "buy"`:
```python
if len(parts) < 3 or parts[0] != "buy":
    raise ValueError("invalid payload format")
```

**Код:**
```python

    user = update.effective_user
    payment = update.message.successful_payment
    payment_id = payment.telegram_payment_charge_id
    payload = payment.invoice_payload

    try:
        parts = payload.split("_")
        if len(parts) < 3:
            raise ValueError("too few parts")
        count = int(parts[1])
        price = int(parts[2])
        if count <= 0 or price <= 0:
            raise ValueError("non-positive count or price")
        valid_pack = next((p for p in BUY_PACKS if p["count"] == count and p["price"] == price), None)
        if valid_pack is None:
            raise ValueError(f"unknown pack count={count} price={price}")
    except Exception as e:
        logger.error("Invalid payment payload %r from user %s: %s", payload, user.id, e)
        await update.message.reply_text("Ошибка обработки платежа. Обратись в поддержку.")
        return

    if payment.total_amount != valid_pack["price"] * 100:
        logger.error("Payment amount mismatch: expected %d kopecks, got %d, user=%s",
                     valid_pack["price"] * 100, payment.total_amount, user.id)
        await update.message.reply_text("Ошибка: сумма платежа не совпадает. Обратись в поддержку.")
        return

    if not save_payment_once(user.id, payment_id, count):
        await update.message.reply_text("Платёж уже обработан.")
        return

    # add_izyminki is now done atomically inside save_payment_once
    new_balance = get_balance(user.id)
```

**Проблема:** После `save_payment_once()` вызывается `get_balance()` БЕЗ гарантии атомарности. Если между `save_payment_once()` (которая добавляет изюминки) и `get_balance()` пользователь потратит часть средств в другом потоке (хотя бот асинхронный, но это всё равно возможно через другие обработчики callback), баланс будет неправильным для отправки.

**Воспроизведение:** 
1. Пользователь платит за 50 изюминок
2. `save_payment_once()` добавляет 50
3. ДО момента `get_balance()` пользователь нажимает кнопку генерации в другом callback
4. `spend_izyminki()` списывает средства
5. `get_balance()` вернёт меньшее число, чем должно было быть (100-50=50 вместо 50)

**Фикс:** Выполнить `get_balance()` ДО любых операций со средствами пользователя, или вернуть баланс из самой `save_payment_once()`.

## 🟢 [SirNike.py:2504] Потенциальная инъекция в regex при парсе WebApp payload

**Код:**
```python
def parse_webapp_payload_loose(raw_data: str) -> Optional[dict]:
    """
    Best-effort parser for malformed/oversized WebApp payloads.
    Helps recover prompt/title when JSON got truncated by WebApp limits.
    """
    text = str(raw_data or "").strip()
    if not text:
        return None

    action_match = re.search(r'"(?:action|a)"\s*:\s*"([^"]+)"', text, flags=re.IGNORECASE)
    title_match = re.search(r'"(?:title|t)"\s*:\s*"([^"]*)"', text, flags=re.IGNORECASE)
    prompt_match = re.search(r'"(?:prompt|p)"\s*:\s*"([\s\S]*)"', text, flags=re.IGNORECASE)

    action = action_match.group(1).strip().lower() if action_match else "set_prompt"
    title = title_match.group(1) if title_match else "шаблон"
    prompt_raw = prompt_match.group(1) if prompt_match else ""
```

**Проблема:** Regex `prompt_match` использует `[\s\S]*` (любые символы) и будет захватывать ВСЁ до конца строки, включая содержимое других полей JSON. Хотя затем идёт попытка обрезать по маркерам (`","example_url"` и т.д.), это неполнота — если поле `prompt` содержит буквально `","` или другой маркер, обрезка сломается.

**Воспроизведение:** Если WebApp отправит промпт вроде:

**Фикс:** Использовать более строгий regex или парсер JSON с fallback:

## 🔴 [SirNike.py:1320] Потеря реферального бонуса при ошибке (race condition в откате)

**Код:**
```python
if referrer_id and is_new_user and mark_referral_bonus(user.id):
    try:
        add_izyminki(user.id, REFERRAL_BONUS_NEW_USER)
        try:
            add_izyminki(referrer_id, REFERRAL_BONUS_REFERRER)
        except Exception:
            # Откатываем бонус новому пользователю, если реферреру не начислилось
            add_izyminki(user.id, -REFERRAL_BONUS_NEW_USER)
            raise
```

**Проблема:** Если `add_izyminki(referrer_id, ...)` упадёт, то `add_izyminki(user.id, -REFERRAL_BONUS_NEW_USER)` выполнится. Но если **этот откат** тоже упадёт (например, БД временно недоступна), новый пользователь останется с бонусом, а реферрер — без. Нет гарантии atomicity на уровне DB.

**Воспроизведение:** 
1. Пользователь регистрируется по реферальной ссылке
2. Новому юзеру начисляется `REFERRAL_BONUS_NEW_USER`
3. Реферреру выдаёт ошибку сети/БД при попытке начисления
4. Откат (`-REFERRAL_BONUS_NEW_USER`) тоже падает
5. Реферрер не получит бонус, но new user получит → асимметрия, потеря revenue

**Фикс:** Обернуть обе операции в одну DB-транзакцию, либо использовать флаг `mark_referral_bonus()` только если **обе** операции успешны:
```python
if referrer_id and is_new_user:
    try:
        add_izyminki(user.id, REFERRAL_BONUS_NEW_USER)
        add_izyminki(referrer_id, REFERRAL_BONUS_REFERRER)
        mark_referral_bonus(user.id)  # только после обеих операций
    except Exception:
        # откатить обе, если вторая упала
        try:
            add_izyminki(user.id, -REFERRAL_BONUS_NEW_USER)
            add_izyminki(referrer_id, -REFERRAL_BONUS_REFERRER)
        except:
            pass
        raise
```
