# Живой UX-аудит бота (Telegram Desktop, аккаунт админа)

Дата: 2026-07-07
Метод: ручной прогон @sirnikebot через computer-use в Telegram Desktop под
аккаунтом Анны (админ). Сверка каждой находки с кодом SirNike.py на main
(HEAD 4afd9ef) + перепроверка находок из audits/2026-07-02_qa_live_retest.txt.
Прод на момент прогона — свежий деплой (навигация 7 кнопок, компактные
клавиатуры, edit-in-place панели видео уже видны в бою).

Проверено живьём: /start, инлайн- и reply-меню, видео-панель (переключатели
модель/качество/формат/длительность, запуск на пустом черновике), фото с
подписью одним сообщением, реальная генерация фото (результат + файл),
библиотека из инлайн-кнопки и из reply-кнопки → «Использовать» (карточка
«Полароид: встреча с собой из детства», 2 фото), /ref.

🔴 КРИТИЧНОЕ

### 1. «Использовать» из библиотеки, открытой ИНЛАЙН-кнопкой — бот молчит,
    стиль не применяется (регресс фикса «библиотека в 1 клик», a40cecc)

Шаги: результат генерации → инлайн-кнопка «📚 Библиотека стилей» (webapp
открылся в 1 клик) → карточка стиля → «Использовать». WebApp закрывается,
бот НЕ отвечает ничего. Воспроизведено дважды. Контрольный прогон через
НИЖНЮЮ reply-кнопку «📚 Библиотека стилей» — работает («Вы успешно передали
данные боту…» → «Готово ✨ Стиль … применён»).

Причина: Telegram.WebApp.sendData() доставляет данные боту ТОЛЬКО из
мини-аппа, открытого через KeyboardButton (reply-клавиатура). Для
InlineKeyboardButton(web_app=…) sendData не работает by design (нужен
answerWebAppQuery, которого в вебаппе нет). Фикс «1 клик» повесил web_app
на инлайн-кнопки main_menu_kb/result_actions_kb — и молча сломал
«Использовать» из этих точек.

ФИКС (в этом же аудите): web_app убран с инлайн-кнопок, возвращён
callback-путь (pl_open_webapp → бот шлёт reply-кнопку «Открыть библиотеку»).
1-клик остаётся на нижней reply-клавиатуре — там KeyboardButton и sendData
работает. Хочется 1-клик и с инлайн — нужен answerWebAppQuery на стороне
вебаппа (бриф фронтенду).

### 2. Текст после неудачного «Запустить видео» уходит в фото-флоу
    (регресс №2 из qa_live_retest ЖИВ в проде, фикс был неполным)

Шаги: «Видео для Reels» → пустой черновик → «🚀 Запустить видео» → бот верно
отвечает «Для видео нужно хотя бы одно: описание или фото» → пишу «кот
играет с мячиком» → ответ «Описание сохранено ✅ Отправь своё фото…»
(фото-флоу) вместо сохранения в видео-черновик. Панель видео на экране.

Причина: фикс переносил деактивацию video_session_active в run_seedance
(после списания изюминок), но CALLBACK-хэндлеры гасили флаг ДО вызова
run_seedance: video_start (state.video_session_active=False перед
create_task), seedance_retry, video_longer_/upgrade. Early-return внутри
run_seedance уже не мог ничего спасти — флаг убит снаружи.

ФИКС (в этом же аудите): преждевременная деактивация убрана из всех трёх
хэндлеров; run_seedance — единственная точка деактивации (после списания),
теперь гасит и waiting_for_video_prompt/waiting_for_video_image, чтобы
фото во время генерации не утекали в видео-буфер.

🟡 СРЕДНЕЕ

### 3. «Использовать» из ПОИСКА библиотеки применяет чужие title/upload_hint

Шаги: reply-кнопка «Библиотека» → поиск «полароид» → карточка «Полароид:
встреча с собой из детства» (📎 Фото сейчас + детское фото) → «Использовать»
→ бот: «Готово ✨ Стиль «Портреты» применён. 📎 Что загрузить: Фото своего
лица + фото партнёра (отдельно)». Название и подсказка — от ДРУГОГО стиля.

Гипотеза: вебапп при активном поиске/фильтре шлёт cat_idx/item_idx
относительно отфильтрованного списка, бот резолвит их по полному
PROMPT_LIBRARY и попадает в чужой item. Промт, вероятно, уходит правильный
(он в payload), но пользователь читает чужую подсказку «что загрузить» и
загружает не те фото. Это вебапп-баг (отдельное репо) — бриф фронтенду.

ФИКС на стороне бота (в этом же аудите): если prompt пришёл в payload и не
совпадает с prompt резолвленного по индексам item — индексы игнорируются
(лог «webapp payload index mismatch»), бот не показывает чужой title/hint.

================================================================
ЧТО ПОДТВЕРЖДЕНО РАБОТАЮЩИМ (живой прогон)
================================================================
- Reply-клавиатура: 7 кнопок по спеке навигации, «Улучшить фото» на месте,
  «Баланс»/«Как пользоваться» совпадают с инлайн-меню буква в букву,
  вебапп-значок на «Библиотеке» (1 клик снизу работает, sendData доходит).
- Инлайн-меню /start: компактная сетка 2×N, «Баланс» без «и пополнение».
- Видео-панель: дефолт 9:16 ✅, переключение модели/качества/формата/
  длительности редактирует ОДНУ карточку на месте (без спама сообщениями),
  цены пересчитываются (Fast 5с·15 → Seedance 2 10с·70).
- Фото + подпись одним сообщением: подпись сразу становится промтом
  («Описание уже есть: «…» Всё готово — запускай!»).
- Результат генерации: подпись объясняет «Модель картинок», предупреждает
  про файл следующим сообщением; файл идёт без дублирующей подписи.
- «Использовать» с reply-кнопки: имя стиля в сообщении (не «Шаблон»),
  upload_hint показывается, клавиатура не пропадает. (Но см. №3 про поиск.)
- Фантомных реф-фото не было: на чистый промт бот ответил «Отправь своё
  фото…», а не «Фото на месте (N шт.)».
