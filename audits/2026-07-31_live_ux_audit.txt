# Живой UX-аудит бота (Telegram Desktop, аккаунт админа) — месяц спустя

Дата: 2026-07-31
Скоуп: полный свежий прогон — прошлый отчёт (2026-07-07) устарел, за месяц
108 коммитов на main (студия нейромультиков Ф1-Ф3, баг-баунти, Kling/Seedance
4:3+1080p, реорганизация меню на «Фото»/«Видео» разделы). Проверено: /start и
оба меню, подменю «Фото»/«Видео», студия нейромультиков (существующий проект
из 5 сцен), видео-панель (новые модели Kling 3.0/Veo 3.1/Wan 2.7, форматы

библиотека стилей (категории + «Новинки», оба входа — инлайн и reply-кнопка).
Метод: ручной прогон через computer-use + сверка каждой находки с кодом
SirNike.py на main (HEAD faa8fce).

### 1. Стили из вкладки «Новинки» не применяются — 2 разных отказа
    в зависимости от входа

Шаги: «📚 Библиотека стилей» (любой вход) → вкладка «Новинки» (первая
секция, видна по умолчанию) → карточка → «Использовать».

а) Через инлайн-кнопку («Библиотека стилей» из главного меню или из
   поста, answerWebAppQuery-путь, инлайн-1-тап): бот отвечает
   «Не удалось применить стиль. Попробуй ещё раз.» — стиль НЕ применяется
   вообще, промт не сохраняется. Воспроизведено дважды на разных карточках.

б) Через reply-кнопку внизу (`sendData`-путь): стиль ПРИМЕНЯЕТСЯ (промт
   сохраняется верно), но название всегда «Стиль «шаблон» применён» — тот
   самый баг из аудита 2026-07-02/07-07, который считался закрытым.

Причина одна и та же: cat_idx/item_idx, которые WebApp шлёт для карточек
из «Новинки», не соответствуют реальной позиции стиля в PROMPT_LIBRARY
(«Новинки», видимо, синтетическая подборка последних стилей по дате, а не
секция с честными индексами). Бот это обнаруживает:

- `apply_webapp_prompt_payload_v2` (SirNike.py:3677-3814) с 07-07 добавил
  защиту от несовпадения (3722-3745: если строка `item_prompt` по резолву
  индексов не совпадает с присланным `prompt` — индексы игнорируются,
  `item = None`). Это верно предотвращает показ ЧУЖОГО title/hint (закрытая
  находка #3 от 07-07), но откатывает title к литералу «шаблон» (3698),
  потому что «Новинки»-карточки не шлют title в payload напрямую.
- `pl_use_`/`pl_usen_` callback (SirNike.py:5227-5248, инлайн-1-тап) такой
  защиты не имеет вообще: `PROMPT_LIBRARY[cat_idx]["items"][item_idx]`
  падает на несовпадающих индексах → `except Exception` (5246) → полный
  отказ, промт не сохраняется, юзер должен «попробовать ещё раз» — и
  получит ту же ошибку снова, потому что проблема не в сети, а в данных.

ФИКС: WebApp должен слать для «Новинки» ИСТИННЫЕ cat_idx/item_idx (позицию
в реальной категории), а не позицию в агрегированном списке — бриф
фронтенду (репо вебаппа). На стороне бота — минимум для pl_use_/pl_usen_:
при несовпадении промта по индексам не проваливаться в «Не удалось
применить», а как в v2 — резолвить title через fallback и применить
присланный (в payload) prompt, если он есть, вместо голого fail.

### 2. «Склеить мультик» в студии нейромультиков не кликается —
    перекрыт нижней sticky-панелью

Шаги: «Видео» → «Студия мультиков» (webapp) → открыть готовый проект (все
сцены с «Клип ✓») → прокрутить до конца → кнопка «🎬 Склеить мультик».
Кнопка физически перекрыта нижней sticky-панелью «Итого: 0 / Сгенерировать»
— видна только верхняя полоска ~15px, клик по ней ничего не делает (не
доскроллить ниже — это конец списка). Воспроизведено 3 раза с разным
позиционированием клика, ни разу не пришло подтверждение склейки в чат.
Функция готовых сцен (Ф3, «склейка клипов в один ролик», commit 98ae2f0)
физически недостижима для проектов, где сцены заполняют весь видимый
список (5+ сцен — обычный случай для сценария на 5-10 сцен).

Бэкенд-часть (`_studio_api`, `_studio_complete`, SirNike.py:7253-7290)
похоже работает — это чисто фронтенд/layout баг в вебаппе (z-index/высота
sticky-футера не учтена в скролл-контейнере сцен). Бриф фронтенду
(репо вебаппа): либо добавить отступ-паддинг снизу списка сцен размером с
футер, либо не показывать «Итого/Сгенерировать» на экране, где всё уже
сгенерировано (Итого: 0) — там место должно освобождаться под «Склеить».

### 3. Видео-панель показывает несуществующий формат при смене модели

Шаги: панель видео на Seedance 2 Fast → выбрать формат «4:3» → переключить
модель на «Wan 2.7». Строка сводки наверху продолжает показывать
«Формат: 4:3 (классика)», хотя кнопки формата для Wan 2.7 — только 16:9/9:16
(4:3 не показан вообще), и ни одна из двух не отмечена «●» — то есть
реального выбора не видно. Бэкенд не пострадает (SirNike.py:8245-8246
молча нормализует недопустимый aspect_ratio в "16:9" перед вызовом
провайдера для veo31/wan27), но пользователь читает неверный формат в
сводке и не видит, что реально будет использовано.

ФИКС: при смене модели на Wan 2.7/Veo 3.1, если текущий state.video_aspect_ratio
не входит в поддерживаемый набор — сбрасывать его на "16:9" И отражать это
в сводке сразу (не дожидаясь следующего клика по формату).
