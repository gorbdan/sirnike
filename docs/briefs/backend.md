      пересортировывает категории: видео-категории в начало

      `_webapp` репо) индексы `cat_idx`/`item_idx` считает по СЫРОМУ порядку
      из `prompt_library.json` (`library = data` без сортировки, см.
      `flattenLibrary()`). Пока «Seedance 2» была первой категорией в файле
      И на сервере — сортировка ничего не меняла, баг был не виден. Как

      в сыром файле — сортировка бота переставила их обратно: `cat_idx=1` у

      инлайн-1-тап `pl_use_`/`pl_usen_`, showcase `shc_`) для ЛЮБОГО стиля,
      чей реальный индекс в сыром файле не совпадает с индексом после
      сортировки бота — то есть для всех категорий после первой
      video-категории в сыром порядке, если перед ней есть хоть одна
      не-видео категория. Сейчас это «Руферы» (индекс 0 в файле, видео нет)
      и всё, что после «Seedance 2».

      `load_prompt_library()` полностью, отдавать категории в сыром порядке

      вебаппа, не трогая индексы) — самый надёжный вариант, раз контракт
