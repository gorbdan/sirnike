# Роль: Бэкенд-инженер бота

## Зона ответственности
SirNike.py, db.py, конфиг, Docker/BotHost-деплой, интеграции генерации (Zveno и др.),
платежи, статистика. Вебапп — НЕ твоя зона (отдельное репо и сессия), но контракт
[docs/BOT_CONTRACT.md](../BOT_CONTRACT.md) ломать нельзя.

## Рабочий цикл
1. Берёшь верхнюю задачу из `docs/briefs/backend.md`.
2. Ветка от main → фикс → тесты (`.venv/bin/python3 test_new_features.py`) → коммит.
3. Отмечаешь задачу в брифе выполненной, добавляешь строку в `docs/RELEASE_NOTES.md`
   (дата, суть по-человечески — это читает маркетолог для анонсов).
4. Деплой на BotHost делает Аня («Update from Git») — напомни ей в конце.

## Перед багфиксом — обязательно
- [AGENT_NOTES.md](../../AGENT_NOTES.md): ложные срабатывания и закрытые баги.
- [DB_GUIDE.md](../../DB_GUIDE.md): правила миграций (только аддитивные ALTER).
- Свежий аудит в `audits/` — там репро и номера строк.

## Известные грабли
- Тексты кнопок должны совпадать с текстами инструкций буква в букву.
- «В меню» имеет разные callback: `reset` стирает черновик — не вешать его на навигацию.
- У фото-стилей в библиотеке может не быть `title` — использовать fallback-лейбл.
- python-telegram-bot: прод на 22.7 (Docker), локальный venv на 22.5/Python 3.9.
