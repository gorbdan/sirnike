# ТЗ: 1-тап «Использовать» с инлайн-кнопок — нужно решение по архитектуре

Автор: фронтенд-сессия. Адресат: бэкенд. Аня подтвердила направление
(«посоветуемся с бэкендом») — этот файл описывает состояние и варианты,
финальную архитектуру выбирает бэкенд-сессия вместе с Аней (вопрос секретов).

## Текущее состояние (проверено в коде, не только по аудиту)

Инлайн-кнопки «📚 Библиотека стилей» (`main_menu_kb`, `result_actions_kb` и др.)
сегодня **не ломают** «Использовать» — они безопасны, но требуют 2 тапа:

1. Тап по инлайн-кнопке → `pl_open_webapp` → бот шлёт «Открывай библиотеку по
   кнопке ниже:» + **новую reply-клавиатуру** (`webapp_open_kb`, `KeyboardButton`
   с `web_app`).
2. Тап по этой reply-кнопке → вебапп открывается через keyboard-button-launch →
   `Telegram.WebApp.sendData()` работает штатно → «Использовать» доставляет payload.

Прямое прикрепление `web_app=` к `InlineKeyboardButton` (функция `webapp_inline_kb`
в SirNike.py) — **мёртвый код, нигде не вызывается**. Именно эта прямая
привязка когда-то молча ломала sendData (audits/2026-07-07_live_ux_audit.txt,
№1) и была откачена на нынешний безопасный 2-таповый путь. Регресса сейчас нет.

## Цель

Довести инлайн-путь до 1 тапа, не потеряв надёжность.

## Почему это не решить только на фронтенде

`Telegram.WebApp.sendData()` документированно работает только для Web App,
запущенного через `KeyboardButton` (reply-клавиатура). Для Web App, открытого
через `InlineKeyboardButton` с `web_app=`, клиент получает в `initDataUnsafe`
поле `query_id` — но отправить результат в чат может только **бот**, вызвав
`answerWebAppQuery(web_app_query_id, result)` (Bot API, требует токен бота).
Значит между вебаппом (Cloudflare Pages) и вызовом `answerWebAppQuery` должен
быть сервер с доступом к `BOT_TOKEN`, который: (1) проверяет HMAC-подпись
`initData` (защита от подделки), (2) вызывает `answerWebAppQuery`.

Результат `answerWebAppQuery` — это **новое сообщение от имени бота**, а не
`message.web_app_data` — значит его нужно оформить так, чтобы бот мог обработать
выбор: например `InlineQueryResultArticle` с инлайн-кнопкой `callback_data=
f"pl_use_{cat_idx}_{item_idx}"` — этот callback уже обрабатывается в
`button_handler` (тот же путь, что у инлайн-каталога библиотеки в самом боте).
Так основную логику применения стиля дублировать не придётся.

## Два варианта — бэкенду выбрать

**A. Бот сам обслуживает запрос.** SirNike.py поднимает лёгкий HTTP-эндпоинт
(или существующий вебхук-сервер), вебапп шлёт туда `{initData, cat_idx, item_idx,
note}`, бот проверяет подпись и вызывает `context.bot.answer_web_app_query(...)`.
Плюс: `BOT_TOKEN` остаётся в одном месте (BotHost). Минус: новая публичная
HTTP-поверхность у бота, требует аккуратной защиты (rate-limit, только POST,
только валидный initData).

**B. Cloudflare Function в репо вебаппа.** Тот же вызов делает функция на
Cloudflare Pages. Плюс: не трогает бот-процесс. Минус: `BOT_TOKEN` нужно
продублировать в секреты Cloudflare — тот же чувствительный секрет в двух
местах, больше поверхность утечки. Требует явного решения Ани — заводить
секрет в новом месте она захочет сама.

Рекомендация (не решение): вариант A меньше по риску для секретов, но это
оценочное сравнение — бэкенду виднее фактическую стоимость каждого варианта
в вашей инфраструктуре (BotHost/Docker сейчас не держит публичного HTTP входа
для юзеров, только Telegram polling/webhook — уточнить, что там технически
проще поднять).

## Что сделает фронтенд, когда архитектура выбрана

- В `app.js`: если `tg.initDataUnsafe.query_id` присутствует (открыто с
  инлайн-кнопки) — вместо `tg.sendData()` слать POST на согласованный
  эндпоинт с телом `{init_data: tg.initData, cat_idx, item_idx, note}`,
  дождаться успеха, затем `tg.close()`. Если `query_id` нет (обычный
  keyboard-button путь) — поведение не меняется, `sendData()` как сейчас.
- Обработать сетевые ошибки (эндпоинт недоступен) — показать тост, не звать
  `tg.close()`, чтобы юзер не терял вебапп молча.

## Критерий приёмки

- Тап по инлайн-«📚 Библиотека стилей» → открывается вебапп напрямую (без
  промежуточного сообщения и второй кнопки) → «Использовать» → в чате
  появляется тот же результат, что и при пути с reply-клавиатуры (см.
  `style_applied_message` в SirNike.py).
- Обычный путь через нижнюю reply-клавиатуру не регрессирует.
- initData проверяется по HMAC на сервере — поддельный payload отклоняется.

## Синхронизация

Формат ответа бота (`answer_web_app_query` + `pl_use_*` callback) — часть
контракта, обновить [docs/BOT_CONTRACT.md](../BOT_CONTRACT.md) веткой, где
будет реализация. Не начинать фронтенд-часть до того, как бэкенд подтвердит
вариант A/B и адрес эндпоинта.
