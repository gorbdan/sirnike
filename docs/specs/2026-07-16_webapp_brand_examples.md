# ТЗ: брендовые примеры для карточек вебаппа

⚠️ **Обновление 2026-07-16, после ревью Ани**: изначальная идея — показывать
before/after прямо в карточке каталога — отклонена («создаёт визуальный шум,
хуже видно сам результат»). Решение: карточка/ряд каталога остаётся с ОДНОЙ
картинкой результата (как сейчас), а «до» уходит в детали стиля (модалка,
открывается тапом по карточке) — маленький инсет-бейдж «ДО» поверх основного
превью, показывается только если у стиля есть вторая фотография. Реализовано
и задеплоено (репо вебаппа, коммит 4fdc8d4) — раздел «Формат» ниже актуален
под ЭТО решение, значит нужны ОБЕ фотографии пары, не только «после».

Автор: фронтенд-сессия. Адресат: контент-продюсер. Дополняет уже существующий
пункт P0 в [docs/briefs/content.md](../briefs/content.md) («Библиотека примеров:
20 before/after») — этот файл добавляет технические требования конкретно для
вебаппа, которых в общем брифе нет.

## Зачем

У части карточек в библиотеке стилей (`prompt_library.json`, репо вебаппа)
картинка-пример — непонятного происхождения (не факт, что реальный вывод бота).
Юзер не может убедиться, что это честный результат — подрывает доверие и
конверсию в «Использовать». Пара «было → стало» в деталях стиля — прямое
доказательство в момент, когда юзер уже колеблется, применять ли стиль.

## Формат файла

На КАЖДЫЙ стиль — **два файла**: «после» (результат бота, идёт в карточку
каталога) и «до» (исходное фото человека, идёт только в маленький бейдж в
деталях). Оба — тот же формат:

- **Соотношение сторон**: вертикаль, как в существующих примерах —
  `previews/rufer_cat_spire.jpg` (768×1376, ≈9:16). Обрезается по центру
  (`object-fit: cover`), так что небольшие отклонения от 9:16 не критичны —
  критично, чтобы важная часть кадра (лицо/композиция) была по центру, а не
  у края, иначе обрежется. Для «до» это особенно важно — бейдж совсем маленький
  (68px), лицо должно быть крупным и по центру, иначе на бейдже не разглядеть.
- **Формат**: JPEG.
- **Размер файла**: ориентир 300–500 КБ для «после» (как текущие примеры).
  «До» может быть заметно легче (бейдж мелкий) — не принципиально.
- **Разрешение**: длинная сторона ~1300–1400 px для «после» достаточно;
  для «до» хватит и меньше (~500–700 px), картинка всё равно уменьшается
  до бейджа.

## Куда класть и как называть

- Файлы — в `previews/` в репо вебаппа (папка уже существует, 2 примера там
  лежат для образца — правда, это одиночные «после», без пары «до», под
  старую версию задачи; можно ориентироваться на них только по формату файла).
- Имя файла: `<короткий_слаг>_<что-то узнаваемое>_after.jpg` и
  `<тот же слаг>_before.jpg` — общий слаг с суффиксом `_before`/`_after`,
  чтобы пара была видна из одних имён файлов (пример:
  `rufer_proposal_after.jpg` + `rufer_proposal_before.jpg`).

## Как передать соответствие «файл → стиль»

Самое важное — это должно быть однозначно, иначе фронтенду придётся гадать.
Формат передачи (как в общем брифе): список строками `стиль → файл`, но
уточнение — «стиль» называть ТОЧНО как в `prompt_library.json`:
- Если у стиля есть `title` (в основном видео-стили и категория «Бьюти») —
  указывать title.
- Если title нет (большинство фото-стилей, это намеренно — см. AGENT_NOTES.md,
  не название стиля пусто просто так) — указывать связку «категория + начало
  description» (например: `С цветами → «Вечерний портрет с букетом белой
  сирени...»`), фронтенд сверит по совпадению и подставит.

Пример строки в списке (теперь два файла на стиль):
```
Руферы → «Предложение с задержанием» → previews/rufer_proposal_after.jpg + previews/rufer_proposal_before.jpg
Портреты → «Пикник для контента...» → previews/portrait_picnic_after.jpg + previews/portrait_picnic_before.jpg
```

Если реального «до» под конкретный пример нет (например, стиль без
чёткого one-to-one результата) — можно прислать только «после», просто
не указывать вторую ссылку в строке. У такого стиля бейдж «до» в деталях
не появится, карточка в каталоге при этом не пострадает — это ок,
необязательное дополнение, не обязаловка на каждый стиль.

## Что сделает фронтенд после получения материалов

Подставит `example_url: "previews/<after-файл>.jpg"` (карточка, было и
раньше) и `before_url: "previews/<before-файл>.jpg"` (новое поле, только
для деталей — если пары нет, поле просто не добавляется) в соответствующих
items `prompt_library.json`. Изменений в коде вебаппа не требуется —
механизм уже реализован и задеплоен, нужны только данные.

## Критерий готовности (для этого конкретного тикета)

Не обязательно все 20 сразу одним пакетом — можно передавать частями по мере
готовности, фронтенд подключит каждую партию отдельным маленьким PR.
