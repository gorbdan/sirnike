# Баг: заглушка answerWebAppQuery портит промт через handle_text

Автор: фронтенд-сессия. Адресат: бэкенд. P0 — ломает только что отгруженный
1-тап («Использовать» с инлайн-кнопок), живой тест Ани 2026-07-17.

## Симптом

После «Использовать» из инлайн-пути (см. [2026-07-15_webapp_inline_1tap.md](2026-07-15_webapp_inline_1tap.md))
в черновике фото вместо реального стиля — служебный текст:

```
✨ Сгенерировать фото
Описание: «📚 Стиль подобран — жми ниже 👇» ✅
```

Хотя должно быть `Стиль: <название> ✅` с настоящим промтом.

## Причина

`functions/answer-webapp-query.js` (репо вебаппа) вызывает `answerWebAppQuery`
с `input_message_content.message_text = "📚 Стиль подобран — жми ниже 👇"` —
это заглушка, задуманная как временная надпись над кнопкой `🚀 Использовать`
(`callback_data=pl_use_{cat_idx}_{item_idx}`), а не как промт.

Telegram вставляет это сообщение в чат — и поскольку это **личный чат
пользователя с самим ботом**, бот получает его повторно как обычный
`message`-update (`update.message.via_bot` = сам бот, но это нигде не
проверяется). `handle_text` (SirNike.py:3005) не распознаёт такое сообщение
как служебное — доходит до низа функции и на строке 3220 делает
`state.prompt = text`, затирая любой ранее выбранный стиль текстом заглушки.

Это гонка с правильным путём: кнопка `🚀 Использовать` под тем же сообщением
корректно резолвит `pl_use_` (SirNike.py:4749, `state.prompt = item["prompt"]`)
— но сообщение с заглушкой прилетает боту раньше или независимо от тапа по
кнопке, и `handle_text` успевает всё испортить первым.

## Фикс (в зоне бэкенда — SirNike.py, хендлер)

В начале `handle_text` (SirNike.py:3005-3011, сразу после
`text = update.message.text.strip()`) добавить ранний выход для сообщений,
отправленных через сам бот:

```python
if update.message.via_bot and update.message.via_bot.id == context.bot.id:
    return
```

Это тот же принцип, что уже применён к `pending_support_reply`/меню-кнопкам
чуть ниже — просто ещё один ранний `return` до того, как текст дойдёт до
`state.prompt = text`.

## Почему это не фронтенд

Фронтенд не может отличить «Telegram доставил нам наше же сообщение повторно»
от «юзер написал текст» — это чисто серверная логика хендлера `handle_text`,
не UI/кнопки/тексты (моя зона). Менять текст заглушки в Cloudflare Function
на что-то похожее на промт — не решение: подмена всё равно будет портить
черновик при любом тексте, если её не отфильтровать на входе.

## Критерий готовности

Тап «Использовать» из инлайн-пути → в чате появляется заглушка → тап по
кнопке `🚀 Использовать` под ней → черновик показывает `Стиль: <реальное
название>`, а НЕ текст заглушки, независимо от того, когда именно Telegram
доставит боту повторную копию заглушки как `message`-update.
