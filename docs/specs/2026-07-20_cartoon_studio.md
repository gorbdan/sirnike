# ТЗ: Студия нейромультиков в вебапе

Дата: 2026-07-20. Заказчик: Аня. Исполнители: бэкенд (репо бота) + фронтенд
(репо вебаппа, gorbdan/_webapp). Статус: черновик на утверждение.

Решения владельца (обсуждение 2026-07-20):
- Сценарий: **оба режима** — ИИ-разбивка идеи на сцены И ручное составление,
  юзер выбирает при создании проекта.
- Оплата: **поштучно, «как корзина»** — смета проекта пересчитывается живьём
  при добавлении/изменении фрагментов, юзер всегда видит итог до запуска.
- Персонализация: **и аватар из профиля бота, и референсы, загруженные
  юзером** — уже в v1.
- Лимит сцен: владелец не задал — берём **5** конфигурируемым параметром
  (`STUDIO_MAX_SCENES`), поднять — одна env-переменная.

## Продукт: флоу юзера (не выходя из вебапа)

1. «🎬 Студия мультиков» → список моих проектов → «Новый мультик».
2. Экран идеи: текст идеи, выбор режима (🪄 ИИ разобьёт на сцены / ✍️ соберу
   сам), референсы (переключатель «использовать мой аватар» + загрузка своих
   фото), формат кадра — **9:16 или 16:9, один на весь проект** (иначе
   склейка кривая; менять после создания нельзя).
3. Раскадровка: сетка сцен. ИИ-режим — сцены с промтами приходят от
   чат-модели, каждую можно править; ручной — юзер добавляет сцены сам.
   У сцены: промт кадра → «Сгенерить кадр» → картинка. Кадр можно
   перегенерить (с правкой промта), сцену — удалить/добавить/поменять порядок.
4. У каждой сцены с готовым кадром: видео-промт (что происходит), модель,
   длительность → цена клипа. Клип = i2v от кадра этой сцены.
5. Корзина-смета внизу: «Итого: N 🍇 · Баланс: M 🍇 · [Сгенерировать
   выбранное]». Генерить можно и по одной сцене, и пакетом.
6. Статусы и готовые клипы — прямо в карточках сцен (плеер). Любой клип
   перегенеривается (другой промт/модель/длительность — цена пересчитается).
7. Все клипы готовы → «🎬 Склеить мультик» → одно видео: плеер в студии +
   бот присылает файл в чат (бэкап и шеринг).

Стыки между сценами — монтажные склейки (каждая сцена стартует со своего
кадра раскадровки). Для мультика это норма; режим «бесшовной» длинной сцены
(last_frame → first_frame) — НЕ в этой фиче (отдельный P1 в брифе).

## Архитектурное ограничение и решение

У бота на BotHost нет публичного HTTP-входа (только polling; вариант A
закрыт окончательно — [2026-07-15_webapp_inline_1tap.md](2026-07-15_webapp_inline_1tap.md)).
Вебапп не может позвать бота напрямую. Решение — **очередь заданий в
Cloudflare D1** (SQLite-база при Pages):

```
вебапп ──(fetch + initData HMAC)──► Pages Functions ──► D1 (projects/scenes/jobs)
                                                          ▲         │
бот (BotHost) ──(поллинг раз в ~4с, секрет)──────────────┘         │
   │ забирает job → биллинг (SQLite бота) → Zveno → результат ─────┘
```

- Авторизация вебаппа: HMAC-проверка `initData` секретом BOT_TOKEN — паттерн
  уже отработан в `functions/answer-webapp-query.js`.
- Авторизация бота: заголовок с секретом `STUDIO_POLL_SECRET` (env и в
  Cloudflare, и в BotHost).
- Биллинг и генерация — ТОЛЬКО в боте (единственный источник правды по
  балансу). Cloudflare не знает ни балансов, ни ZVENO_API_KEY.
- Для видео-генераций (минуты) поллинг в 4с незаметен; вебапп поллит статусы
  своего проекта GET-запросом раз в 3–5с, пока есть активные job'ы.

## Хранение медиа

- **Кадры**: бот заливает на imgbb (`IMGBB_API_KEY` уже в проде) → браузерный
  URL в D1. Резерв: если imgbb недоступен — data:URL превью в D1 (кадры
  маленькие) + полноразмер доедет при ретрае.
- **Клипы и финальное видео**: URL от Zveno в D1 для просмотра в студии +
  бот СРАЗУ шлёт каждый готовый клип и финал юзеру в чат (Telegram = вечный
  бэкап; Zveno-URL может протухнуть — это осознанный риск v1, при протухании
  в студии показываем «клип в чате у бота»).

## Схема D1

```sql
CREATE TABLE studio_projects (
  id TEXT PRIMARY KEY,            -- uuid
  user_id INTEGER NOT NULL,
  title TEXT DEFAULT '',
  idea TEXT DEFAULT '',
  mode TEXT DEFAULT 'ai',         -- ai | manual
  aspect TEXT DEFAULT '9:16',     -- 9:16 | 16:9, фикс после создания
  use_avatar INTEGER DEFAULT 0,
  ref_urls TEXT DEFAULT '[]',     -- JSON: загруженные референсы юзера
  status TEXT DEFAULT 'draft',    -- draft | stitching | done
  final_url TEXT DEFAULT '',
  created_at TEXT, updated_at TEXT
);
CREATE TABLE studio_scenes (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL,
  ord INTEGER NOT NULL,
  frame_prompt TEXT DEFAULT '',
  frame_url TEXT DEFAULT '',
  video_prompt TEXT DEFAULT '',
  model TEXT DEFAULT 'seedance2_fast',
  duration INTEGER DEFAULT 5,
  clip_url TEXT DEFAULT '',
  status TEXT DEFAULT 'empty'     -- empty|frame_queued|frame_ready|clip_queued|clip_ready|error
);
CREATE TABLE studio_jobs (
  id TEXT PRIMARY KEY,
  user_id INTEGER NOT NULL,
  project_id TEXT NOT NULL,
  scene_id TEXT,                  -- NULL для scenario/stitch
  type TEXT NOT NULL,             -- scenario | frame | clip | stitch
  payload TEXT DEFAULT '{}',      -- JSON: промты, модель, длительность, expected_cost
  depends_on TEXT,                -- id job'а, без done которого этот не берётся
                                  -- (batch «кадр+клип одной сцены» одним кликом)
  status TEXT DEFAULT 'queued',   -- queued | taken | done | error
  error TEXT DEFAULT '',          -- not_enough_funds | moderation | provider | price_changed | internal
  result TEXT DEFAULT '{}',
  attempts INTEGER DEFAULT 0,
  created_at TEXT, taken_at TEXT, done_at TEXT
);
```

## API (Pages Functions, все под /api/studio/)

Для вебаппа (POST JSON `{init_data, ...}`, HMAC-проверка):
- `project.create` / `project.get` (+все сцены и активные jobs) /
  `project.list` / `project.delete` / `project.update` (title/idea/use_avatar/ref_urls)
- `scene.upsert` (промты/модель/длительность/порядок) / `scene.delete`
- `enqueue` — job(ы): `scenario` (ИИ-разбивка), `frame` (кадр сцены),
  `clip` (клип сцены), `batch` (массив frame/clip), `stitch`.
  Перед постановкой Function валидирует лимит сцен и что у clip есть кадр.
- `prices.get` — прайс-лист для корзины (см. Биллинг).

Для бота (заголовок `X-Studio-Secret`):
- `poll` — атомарно берёт до N queued-jobs (`UPDATE ... SET status='taken'
  WHERE id IN (SELECT ... LIMIT N)` — D1 сериализует записи, гонок нет).
- `complete` — результат job'а (result/error) + обновление сцены/проекта.
- `prices.push` — бот при старте пушит актуальный прайс (источник правды —
  config.py бота; корзина в вебапе считает по этим числам, финальное
  списание ВСЕГДА по боту).

## Биллинг («корзина»)

- Смета на клиенте: кадр = цена фото (BASE_GENERATION_COST, 5 🍇; с
  референсами — + REFERENCE_COST как в боте), клип = секунды × тариф модели
  (те же тарифы, что в видео-панели бота), ИИ-разбивка сценария и склейка —
  бесплатно. Итог пересчитывается при каждом изменении корзины.
- Списание — в боте, в момент взятия job'а: проверка баланса → списание →
  генерация; ошибка генерации → возврат (паттерн run_generation/run_seedance).
- Не хватает на весь batch — бот выполняет что хватает по порядку сцен,
  остальным ставит `error=not_enough_funds`; вебапп показывает «Не хватает
  N 🍇 · [Пополнить]» (кнопка ведёт в чат бота на оплату).
- Админы (ADMIN_IDS) — бесплатно, как везде.

## Генерация на боте (воркер)

Новый asyncio-таск `_studio_poll_loop` (запуск из post_init, как
`_daily_top_styles_push_loop`): каждые ~4с poll → на каждый job:
- `scenario`: ZVENO_CHAT_MODEL, промт «разбей идею на N сцен, каждой — промт
  кадра и черновой видео-промт, JSON» → пишет сцены в D1 (через complete).
- `frame`: генерация картинки как generate_image_by_job (референсы: аватар
  юзера если use_avatar, + ref_urls проекта), aspect проекта → imgbb → URL.
- `clip`: i2v как run_seedance (кадр сцены = image reference, модель/
  длительность из payload, аспект проекта) → URL + отправка клипа в чат.
- `stitch`: скачать все клипы → ffmpeg: нормализация (единый fps/размер/
  кодек h264+aac, у моделей разные параметры; клипам БЕЗ аудиодорожки —
  тихая дорожка anullsrc, иначе concat с миксом «Kling со звуком + Seedance
  без» падает) → concat → финал в чат юзеру + результат в D1.
  **Dockerfile: добавить ffmpeg** (проверить, что BotHost собирает с apt —
  иначе static-бинарь).
- **Конкурентность**: студийные джобы НЕ идут через generation_queue бота —
  у GenerationJob/run_seedance результат шлётся в чат, а кадры студии в чат
  слать нельзя (спам). Из generate_image_by_job/run_seedance выделяются
  «ядра» (генерация → URL, без чата и без своего биллинга), студийный воркер
  зовёт их напрямую: глобальный семафор на ~3 одновременных джобы, внутри
  юзера — строго последовательно (клип может идти 20+ минут — один воркер
  на всех заблокировал бы студию намертво). Гварды queued_user_ids чата НЕ
  трогаем: генерация в чате и в студии друг друга не блокируют.

## Ревизия на баги (2026-07-20, до старта — найдено и вшито в ТЗ)

1. **Зависшие джобы**: бот взял job (`taken`) и умер/перезапустился →
   job висит вечно. Фикс: `poll` возвращает в `queued` всё, что в `taken`
   дольше 40 мин (клип легально генерится до 25 мин — порог с запасом),
   `attempts += 1`; после 3 попыток — `error=internal` с возвратом денег.
2. **Двойное списание**: бот списал, сгенерил, а `complete` не дошёл по
   сети → job вернётся в очередь → повторная генерация и повторное списание.
   Фикс: локальная таблица в SQLite бота `studio_done_jobs(job_id, charged,
   result)` (переживает рестарт, DATA_DIR) — перед списанием проверка;
   повторное взятие уже сделанного job'а = только ре-отправка `complete`,
   без генерации и списания.
3. **Batch «кадр+клип» одной кнопкой**: клип нельзя ставить в очередь без
   готового кадра, но юзер хочет «сделать всё» одним кликом. Фикс: поле
   `depends_on` — клип ссылается на job кадра, poll не отдаёт job, пока
   зависимость не `done` (ошибка зависимости → каскадный `error`).
4. **Дубли от даблтапа**: два тапа «Сгенерить» = два оплаченных job'а. Фикс:
   `enqueue` отклоняет job, если по той же сцене уже есть queued/taken job
   того же типа.
5. **Расхождение цены**: юзер видел в корзине одну цену, бот списал другую
   (тарифы обновились между рестартами). Фикс: payload несёт `expected_cost`,
   бот пересчитывает по своим тарифам — не сошлось → `error=price_changed`
   без списания, вебапп обновляет прайс и переспрашивает. Прайс-фид
   (`prices.push`) обязан включать и допустимые длительности по моделям —
   иначе корзина посчитает 7с для Veo (который умеет только 4/6/8) и цена
   разойдётся со снэпнутой.
6. **Загрузка референсов из вебапа**: вебапп не может лить фото на imgbb
   напрямую (ключ светить нельзя). Фикс: клиент ужимает до ~1024px JPEG →
   POST в Function → Function заливает на imgbb (ключ — секрет Cloudflare).
7. **Подмена user_id/чужие проекты**: `user_id` берётся ТОЛЬКО из
   HMAC-проверенного initData (никогда из тела запроса), каждая операция
   проверяет владельца проекта; initData старше 24ч — отказ.
8. **Склейка без звука**: у Seedance/Wan клипы без аудиодорожки, у
   Kling/Veo — со звуком; ffmpeg concat такого микса падает. Фикс — в
   описании stitch (тихая дорожка).
9. **Перегенерация кадра после готового клипа**: клип остаётся (не
   стирается молча — юзер за него платил), сцена помечается «кадр обновлён
   позже клипа» — UI показывает подсказку «перегенерить клип?». Stitch
   валидирует: ≥2 сцен со статусом clip_ready, склейка только их, по ord;
   `complete` по удалённому проекту — no-op без ошибки.

## Критерий приёмки (живой, на проде)

Идея → ИИ-разбивка на 3 сцены → кадры (одна сцена с аватаром) → правка
промта одного кадра + перегенерация → 3 клипа (разные модели) →
перегенерация одного клипа → склейка → финал играет в студии и пришёл в
чат. Баланс списан ровно по смете корзины. Ручной режим: проект на 2 сцены
без ИИ — работает тот же путь.
