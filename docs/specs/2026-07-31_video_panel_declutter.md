# ТЗ: причесать видео-панель — не спрашивать модель дважды

Дата: 2026-07-31. Автор: фронтенд-сессия. Адресат: бэкенд. Статус: макет
утверждён Аней («причеши раздел "видео рилс", убери выбор модели, когда она
уже выбрана — там бардак»). Первая задача под новое правило: правки SirNike.py
теперь у бэкенда, фронтенд только пишет ТЗ (см. docs/roles/backend.md,
docs/roles/frontend.md, обновлены сегодня).

## Контекст

`video_model_picker_kb()` (SirNike.py, добавлена PR #86 — экран «сначала
только выбор модели» вместо полной панели сразу) сейчас показывается **при
каждом** входе в «🎬 Видео для Reels», даже если юзер уже выбирал модель
раньше в этой же сессии. Плюс полная панель (`video_kb`) держит модель
целым блоком кнопок (`model_buttons`/`model_buttons_extra`, до 2 рядов, до
6 кнопок), хотя модель уже написана текстом в шапке (`video_status_text`,
строка «Модель: …»). Итог — юзер выбирает модель, видит её же список кнопок
второй раз в той же панели, и при следующем заходе в видео — снова с пикера.

## Часть 1 — не показывать пикер повторно

1. `UserState` (dataclass, рядом с `video_model: str = "seedance2_fast"`):
   добавить `video_model_picked: bool = False`.
2. Ветка `video_cb.startswith("video_model_")` в `button_handler` (там, где
   резолвится `picked_model` и вызывается `update_video_panel`) —
   дополнительно ставить `state.video_model_picked = True`.
3. Оба входа в видео-флоу — сейчас оба безусловно шлют
   `video_model_picker_kb()`:
   - `button_handler`, ветка `video_cb == "video"`;
   - `handle_menu_button`, ветка `text == MENU_BTN_VIDEO`.

   Изменить на условие: если `state.video_model_picked` — сразу слать полную
   панель (`video_status_text(state)` + `video_kb(state)`), как было ДО PR
   #86; если нет — как сейчас, `video_model_picker_kb()`.
4. `reset` callback (`query.data == "reset"`) уже переносит «липкие»
   настройки в новый `UserState` (`new_state.image_model = prev_state.image_model`)
   — по этому же образцу добавить перенос `video_model` и
   `video_model_picked`. Без этого шага флаг и выбранная модель будут
   слетать при каждом «◀️ В меню», и часть 1 не даст эффекта.

## Часть 2 — убрать модель из полной панели, оставить одну кнопку «сменить»

В `video_kb(state)`:

- Удалить блок, собирающий `model_buttons`/`model_buttons_extra`, и строки
  `rows.append(model_buttons)` / `if model_buttons_extra: rows.append(...)`.
- На их месте — один ряд с одной кнопкой:
  `InlineKeyboardButton("🔄 Сменить модель", callback_data="video_change_model")`.
- Модель как факт уже видна в `video_status_text` (строка «Модель: …») —
  дублировать её кнопками-переключателями внутри полной панели больше не
  нужно.

Новая ветка в `button_handler`:

```python
if video_cb == "video_change_model":
    state = get_or_init_state(context)
    await update_video_panel(query, "🎬 Видео для Reels\n\nВыбери модель:", video_model_picker_kb())
    return
```

(тот же паттерн edit-in-place, что уже применяется у `video_model_*` через
`update_video_panel` — новое сообщение не шлётся, правится текущее).

⚠️ `video_change_model` нужно добавить и в `video_callbacks`/проверку
`is_video_callback` (сейчас там `video_cb.startswith("video_model_")` для
самих кнопок модели — `video_change_model` под этот префикс не попадает,
добавить отдельно, иначе тап при выключенном `SEEDANCE_ENABLED` не
заблокируется корректно).

## Что НЕ меняется

- `video_model_picker_kb()` и её кнопки (`video_model_*`) — уже реализованы
  (PR #86), переиспользуются как есть, менять не нужно.
- Ветка `video_cb.startswith("video_model_")`, которая резолвит модель и
  зовёт `update_video_panel` — трогать только в части добавления
  `state.video_model_picked = True` (п.2 части 1), остальная логика модели
  (Seedance/Kling/Veo/Wan/Gemini Omni, форматы, длительности) не меняется.
- `video_status_text()` — без изменений, строка «Модель: …» там уже есть.

## Критерий приёмки

1. Свежий юзер (или после `reset`) → «🎬 Видео для Reels» → видит ТОЛЬКО
   пикер моделей → выбирает модель → то же сообщение становится полной
   панелью, БЕЗ рядов кнопок-моделей (только «🔄 Сменить модель»).
2. Тот же юзер, БЕЗ `reset`, выходит в меню (`menu_from_video`, который
   черновик не стирает) и снова жмёт «🎬 Видео для Reels» → сразу полная
   панель с той же моделью, пикер не показывается.
3. Тап «🔄 Сменить модель» в полной панели → то же сообщение становится
   пикером; выбор новой модели → снова полная панель, уже с новой моделью.
4. Оба входа (инлайн-кнопка и reply-кнопка `MENU_BTN_VIDEO`) ведут себя
   одинаково по пп. 1–2.
5. `.venv/bin/python3 test_new_features.py` — 0 FAIL, включая существующие
   тесты 3.36–3.37 (пикер без настроек) и `video_kb`-тесты 3.1–3.9 (там
   проверялись `video_model_*` callback'и в `video_kb` — после удаления
   этих кнопок тесты нужно поправить под новую структуру, не просто
   удалить проверку).
