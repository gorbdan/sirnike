# Спека: Радикальное упрощение меню бота + «Улучшить фото» в вебапп

Дата: 2026-08-14. Продуктовое решение Ани поверх уже собранного Хаба
генерации (`docs/specs/2026-08-13_webapp_generation_hub.md` +
`..._navigation_full.md`): раз вебапп теперь закрывает ВСЕ продукты
(Фото/Видео/Аватар/Midjourney через «Создать», Доски, Студия) одним
экраном с единой навигацией — держать те же продукты ЕЩЁ РАЗ отдельными
чат-флоу в меню бота избыточно, это и есть дублирование, а не миграция.
Решение: меню бота сжимается до 3 кнопок, «Библиотека стилей»
переименовывается и становится единственным входом во весь вебапп.

## Почему сейчас, а не раньше

До этой спеки часть продуктов вебаппа (Midjourney/Аватар/Фото-конструктор)
не имела аналога для «Улучшить фото» — растить меню бота дальше, оставляя
в нём один осиротевший продукт без вебапп-экрана, значило бы либо ломать
доступ к нему (если резать меню как есть), либо оставлять два флоу
одновременно (если не резать). Эта спека закрывает последний пробел —
«Улучшить фото» получает свой экран в вебаппе — и тогда резать меню можно
без потери функциональности.

---

## Часть 1 — Улучшить фото → экран вебаппа

### Почему это ПРОЩЕ всех остальных конструкторов

`_cb_enhance_photo` (SirNike.py:6377) уже сегодня — фиксированный промт
(`ENHANCE_PHOTO_PROMPT`, юзер его не видит и не редактирует), фиксированная
модель (`gemini`, «nano banana», не переключается), юзер присылает РОВНО
одно фото. Экрану конструктора вообще не нужны текстовые поля — только
загрузка одного фото и кнопка запуска. Ближе всего к `photo_constructor.js`
(тот же паттерн: `tg.sendData()` → один payload → карточка подтверждения в
чате → существующий коллбэк запуска), но даже проще — без описания и без
переключателя модели.

### Экран (вебапп, новый файл `enhance_constructor.js`/секция в index.html)

```
🖼️ Улучшить фото

Пришли фото, которое нужно улучшить
[ фото ✕ ]  (максимум 1 — второе заменяет первое, не добавляется)
[ + добавить фото ]

Бот повысит качество и сделает его похожим на кадр от профессионального
фотографа — черты лица останутся прежними.

[     🚀 Продолжить в чат     ]  (активна только когда фото загружено)
```

Кнопка неактивна без фото — принцип «кнопка есть ⇔ действие сейчас
возможно», как у всех остальных конструкторов.

### Контракт payload — расширение `start_generation`, НЕ новое действие

```json
{"action": "start_generation", "product": "enhance", "refs": ["<url загруженного фото>"]}
```

- `refs` — ровно 1 URL (уже захостенный на imgbb, тот же аплоадер, что у
  остальных конструкторов). Больше одного — бот берёт первый, не ошибка.
- Никаких `description`/`quality`/`aspect` — фиксировано на стороне бота,
  как и сегодня в `_cb_enhance_photo`.

### Бэкенд

1. Новая ветка `product == "enhance"` в диспетчере `apply_webapp_generation_payload`
   (тот же диспетчер, что уже обслуживает video/midjourney/avatar/photo —
   НЕ новый парсер с нуля). Резолвит: `state.prompt = ENHANCE_PHOTO_PROMPT`,
   `state.image_model = "gemini"`, `state.references = [первый url из refs]`
   (тот же паттерн сброса, что уже в `_cb_enhance_photo` — `deactivate_video_session`,
   `state.style_extract = False`).
2. Если `refs` пуст — честный отказ («Нужно фото — вернись и добавь»,
   тот же текст-паттерн, что уже есть у product=video/photo при пустом
   payload), не молчаливое создание пустого состояния.
3. Карточка подтверждения в чате — переиспользует уже существующий
   `photo_draft_text(state, user.id)`/`photo_draft_kb(state, user.id)`
   (та же функция, что заканчивает сегодняшний ручной флоу
   `_cb_enhance_photo` после присылки фото) — **не пишем новый текст
   карточки**, только доводим её до состояния «фото уже есть», минуя шаг
   ожидания сообщения с фото.
4. Фичефлаг `ENHANCE_CONSTRUCTOR_ENABLED` (config.py, дефолт `False`,
   тот же принцип kill-switch, что у `PHOTO_CONSTRUCTOR_ENABLED` и
   остальных). При `False` — `product: "enhance"` в payload отвечает тем же
   «недоступна» отказом, что и остальные отключённые продукты (не крэш).
5. `cfg`/`&features=` — добавить `"enhance": ENHANCE_CONSTRUCTOR_ENABLED` в
   `_generation_hub_features_payload()` (SирNike.py) — плитка/точка входа
   в вебапп должна уметь скрываться так же, как остальные.

### Точка входа

«Улучшить фото» из меню бота **исчезает** как отдельный пункт (см. Часть 2) —
единственная точка входа в этот экран теперь ВНУТРИ вебапп-хаба.
Разместить на экране «Создать» — сетка продуктов расширяется с 4 до 5
плиток: `[ 🖼 Фото ] [ 🎬 Видео ] [ 🪄 Аватар ] [ 🎨 Midjourney ] [ ✨ Улучшить фото ]`
(порядок — на усмотрение фронтенда, критично только не прятать глубоко).
Плитка `enhance` гейтится `features.enhance` тем же приёмом, что и три
остальные (см. уже реализованный `applyGenerationHubFeaturesFromUrl` в
`app.js`, репо вебаппа).

## Часть 2 — Меню бота: только 3 кнопки

### Целевое состояние

`main_menu_kb` (инлайн, SirNike.py:1558) и `persistent_menu_kb` (reply,
SirNike.py:1657) — обе сжимаются до:

```
[ 📚 Библиотека и генерация ]
[ 🐞 Баг-баунти ]  [ 💰 Баланс ]
```

(текст первой кнопки — рабочее предложение, финальную формулировку решает
фронтенд/UX при реализации; требование — не врать, что это «только стили»,
раз внутри теперь всё: Фото/Видео/Аватар/Midjourney/Улучшить фото/Доски/
Студия).

**Убираются** из обоих меню: «📸 Фото», «🎬 Видео» (и их подменю
`photo_menu_kb`/`video_menu_kb` целиком — Midjourney/Аватар/Улучшить
фото/Видео для Reels/Видео с движением/Студия мультиков как ПУНКТЫ МЕНЮ,
не как функциональность — см. «Что НЕ удаляется» ниже), «🎁 Пригласить
друга», «❓ Как пользоваться», «🚨 Проблема».

### Что НЕ удаляется (важно — это не снос функций, а снос ДУБЛИРУЮЩИХ точек входа)

Сами хендлеры/коллбэки (`_cb_menu_photo`, `_cb_menu_video`, `report_problem`,
`open_ref`, `show_help`, вся логика Midjourney/Аватар/Студии/Видео) **не
удаляются из кода** — только перестают быть кнопками в `main_menu_kb`/
`persistent_menu_kb`. Причины:
- `open_ref`/реферальная логика может быть частью уже разосланных ссылок
  (`/start ref_...`) — ломать её нельзя, только прятать саму кнопку-вход.
- `show_help` может быть нужен из других мест (например, автоматическое
  приветствие `/start` у нового юзера — сверить перед удалением, не
  удалять транзитивно).
- Chat-флоу Midjourney/Аватар/Видео (`menu_photo`/`menu_video`
  callback-цепочки) — пока `MIDJOURNEY_CONSTRUCTOR_ENABLED`/
  `AVATAR_CONSTRUCTOR_ENABLED`/`VIDEO_CONSTRUCTOR_ENABLED` не включены на
  100% и не проверены в проде, чат-флоу остаётся рабочим резервным путём
  «на всякий случай» (например, ручной фикс через админку/прямой callback),
  просто без кнопки-входа из главного меню. Удалить эти хендлеры полностью
  — отдельная, более поздняя задача (после того, как Full пройдёт живой
  прод-тест), НЕ часть этой спеки.

### Библиотека — единственный вход во весь вебапп

`_prompt_library_button` (SirNike.py:1542) сейчас форсирует `&tab=library`.
Меняется: НЕ форсировать `tab` вообще — пусть открывается дефолт вебаппа
(«Создать», уже мигрировано в Full-навигации). Это делает кнопку буквально
тем, чем она теперь является — входом во ВЕСЬ хаб, а не только в каталог
стилей. Тексты кнопки везде, где используется (`main_menu_kb`,
`persistent_menu_kb`, возможно другие места — сверить
`MENU_BTN_LIBRARY`/`_prompt_library_button` по всему файлу) — переименовать
синхронно и один раз (одна константа `MENU_BTN_LIBRARY`, не расходящиеся
копии текста).

### Обратная совместимость входов, которые НЕ являются кнопками меню

Инлайн-кнопки на карточках результата («Другой стиль», «Повторить» и
т.п.), deep-link'и, команды `/start` с параметрами — НЕ часть этой спеки,
не трогать, если явно не относятся к `main_menu_kb`/`persistent_menu_kb`.

## Критерий приёмки

- `product=enhance` в `start_generation` работает end-to-end: фото →
  payload → карточка подтверждения (текст = существующий
  `photo_draft_text`) → существующий коллбэк генерации → результат в чат
  — без нового кода в биллинге.
- `ENHANCE_CONSTRUCTOR_ENABLED=false` → честный отказ, не крэш.
- `main_menu_kb`/`persistent_menu_kb` — ровно 3 кнопки (Библиотека,
  Баг-баунти, Баланс), тексты дословно синхронны между обоими меню.
- `_prompt_library_button` открывает вебапп БЕЗ форсированного
  `tab=library` — юзер видит «Создать».
- Существующие хендлеры (Midjourney/Аватар/Видео/реферал/help/report)
  не удалены из кода, только убраны как пункты меню — компиляция и
  весь `pytest tests/` зелёные, ни один существующий тест не должен
  сломаться просто из-за отсутствия кнопки (если тесты дёргают хендлеры
  напрямую по `callback_data`, а не кликом по клавиатуре — они не должны
  быть затронуты).
- `python3 -m py_compile SirNike.py config.py` + весь `pytest tests/`
  зелёные, новые тесты на `product=enhance` и на состав `main_menu_kb`/
  `persistent_menu_kb` (по образцу существующих тестов хаба генерации).
