# Вебапп без выхода в чат: генерация по HTTP-очереди вместо `tg.sendData`

Решение Ани 2026-11-16: «всё в вебаппе». Причина: `sendData()` закрывает Mini App,
юзер прыгает «чат → вебапп → чат». Этап 1 (бэкенд) готов, ждёт фронтенд.

## Принцип
Меняется ТОЛЬКО транспорт. Payload тот же, что сегодня уходит в `tg.sendData()`
(`action:"start_generation"`, `product`, поля конструктора — см. docs/BOT_CONTRACT.md).
Бот забирает его из очереди и прогоняет через те же обработчики (валидация, цена,
биллинг, рефанд, «Остановить», живой прогресс). Отличие одно: задание из очереди
= **подтверждение трат**. Карточку «🚀 Запустить» в чате бот пропускает, генерация
стартует сразу. Поэтому кнопка «Создать» в вебаппе должна показывать цену и быть
явным действием (она уже её показывает — «≈34 🍇»).

Флаг на стороне бота: `WEBAPP_GEN_ENABLED=1` (по умолчанию выключен, поллер не
стартует). Включит Аня, когда фронт выкачен. До этого `sendData`-путь работает как раньше.
Автозапуск реализован для `product`: `video`, `photo`, `avatar`, `midjourney`, `enhance`.
Остаются на `sendData` (они не про трату, а про выбор): доски (`board_refs`/`board_style_analyze`),
`set_active_avatar`, `set_prompt` (подстановка стиля), `topup`. Их бэкенд переведёт следующим этапом.

**Прогресс фото.** Для `photo` бот тоже зеркалит прогресс (`gen_progress_create` с `product` из `photo`/`avatar`/`midjourney`/`video`,
`progress_id == job_id`, закрывается в `done`/`error` по факту доставки результата в чат). Нужно:
1) в `functions/api/progress` разрешить `product` `photo` и `avatar` (если там enum; `video` и `midjourney` уже есть). `enhance` идёт как `photo`; 2) на проде должен быть
`GEN_PROGRESS_ENABLED=1` — иначе `result.progress_id` будет пустым-не-пустым: бот вернёт id, а записи
прогресса не будет. Сам снимок результата (картинка) в вебапп пока НЕ передаётся — готовое фото
приходит в чат; превью в вебаппе — отдельный этап.

## Pages Functions `functions/api/gen/[[action]].js` (репо вебаппа)

Таблица D1 `gen_jobs`:
`id TEXT PK, user_id INTEGER, username TEXT, payload TEXT, status TEXT
('queued'|'taken'|'done'|'error'), error TEXT, result TEXT, attempts INTEGER DEFAULT 0,
created_at, taken_at, done_at`. Индекс по `(status, created_at)` и `(user_id, created_at)`.

### Действия вебаппа (проверка `init_data`, как у `studio` — `verifyStudioUser`)
- `submit` — body `{ init_data, payload: {...как для sendData...} }`.
  Проверки: `payload` объект, ≤ 16 КБ JSON. `user_id`/`username` берутся ИЗ init_data,
  не из body. Дедуп: тот же user + тот же payload (хэш) за последние 10 с →
  вернуть существующий `job_id`. Ответ `{ ok:true, job_id }`.
  Лимит: ≤ 5 заданий в статусе queued/taken на юзера → `429 {error:"too_many"}`.
- `status` — body `{ init_data, job_id }` → `{ ok, status, error, result }` (только свои задания).

### Действия бота (заголовок `X-Studio-Secret` = тот же `STUDIO_POLL_SECRET`, что у студии)
- `poll` — body `{ limit }`. Как `botPoll` студии: вернуть зависшие `taken` старше
  `STALE_TAKEN_MINUTES` в очередь (attempts+1), `attempts >= MAX` → `error:"internal"`,
  атомарно взять `queued` → `taken` через `UPDATE … RETURNING id, user_id, username, payload`.
- `complete` — body `{ job_id, status, error, result }`. Идемпотентно (повторный
  complete = no-op). Записывает `status/error/result/done_at`.

### Что бот кладёт в `result`
```json
{ "accepted": true, "launched": true, "product": "video",
  "progress_id": "<job_id>", "messages": ["…"] }
```
- `status:"done"` + `launched:true` — генерация запущена. `progress_id` равен `job_id`:
  экран прогресса открывается по существующему API `functions/api/progress`
  (`job_id=<progress_id>`, `product=video`) — тот же, что сейчас открывает кнопка
  «👀 Смотреть прогресс». В чате при этом бот пишет обычный статус и присылает готовое видео.
- `status:"error"`, `error:"not_started"` — отказ (нет фото/описания, не хватает
  изюминок, другая задача уже идёт и т.п.). Причина человеческим текстом в `result.messages[0]`
  — **показать её в вебаппе** (тост/плашка под кнопкой), не уходя в чат.
  Бот дублирует её в чат — это нормально.
- `error:"interrupted"` — бот перезапускался во время обработки; деньги повторно не
  списываются, юзеру: «Не получилось, попробуй ещё раз».
- `error:"bad_job"` / `"internal"` — общий сбой.

## Контракт экрана «Создать» (видео — первый, остальные по готовности бэкенда)
1. Кнопка «Создать» → клиентская валидация (поля уже проверяются) → `submit`.
2. Пока ждём ответ — кнопка заблокирована, «⏳ Отправляем…». Опрос `status` каждые 1,5 с,
   до 20 с на сам приём (обычно <5 с: бот поллит раз в 2 с).
3. `done` → перейти на вкладку прогресса (`tab=progress&job_id=<progress_id>&product=video`)
   ВНУТРИ того же вебаппа; **никаких `sendData`/`tg.close()`**.
4. `error` → показать `result.messages[0]` или стандартный текст по коду; поля формы НЕ сбрасывать.
5. Нет ответа 20 с → «Бот занят, попробуй через минуту»; повторный клик не плодит дубли (дедуп на сервере).
6. Рядом с прогрессом — кнопка «Остановить»: пока она остаётся в чате (`video_cancel_gen`);
   веб-версию бэкенд добавит отдельным этапом (скажу в брифе).

## Критерии приёмки
- Видео из вебаппа: «Создать» → прогресс в вебаппе → готовое видео в чате, вебапп не закрывался.
- Пустое описание/без фото → ошибка внутри вебаппа, изюминки не списаны.
- Двойной клик → одно задание.
- С `WEBAPP_GEN_ENABLED=0` фронт не должен падать: если `submit` отвечает 404/5xx —
  откат на прежний `sendData` (так безопасно катить до включения флага).
